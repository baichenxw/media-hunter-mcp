# 0.2.0 重构与验收记录

日期：2026-09-09（北京时间）。

## 交付内容

保留原有四站支持及六个 MCP 工具名称；已有 `config.toml` 未修改，下载根目录、代理与凭证继续沿用。

核心代码分为 MCP 接入、应用服务、站点协议、网络请求、下载引擎五层，新增独立命令行。Pixiv 从同步 pixivpy3 改为原生异步 OAuth/App API，移除 requests/cloudscraper 等同步依赖。

主要修复：

- 网络逐次限速、有限重试、Retry-After；明确区分认证、配额、不存在和网络错误。
- 下载改为流式临时文件与原子落盘，避免大文件整块占用内存；拒绝空文件、截断响应和 HTML 错误页。
- 下载总超时覆盖排队、搜索/详情、解析和传输；取消时停止异步任务，清理临时文件并终止合成进程。
- 批量下载最多尝试 50 个文件；超出剩余额度的画廊整本跳过，支持单独下载整本。
- E-Hentai 分类直接提交站点，搜索跟随 Next 游标；画廊按实际缩略图分页遍历，逐页下载前才解析图片地址。
- E-Hentai 同一分组下的不同画廊各自独立，避免 `001.jpg` 与 `gallery.json` 相互覆盖。
- 单文件失败保留其他成功文件，sidecar 记录完成、部分失败或取消状态；原始 ugoira 的帧顺序与延时写入元数据。
- Pixiv 自动续期令牌，识别 API 错误对象与 medium ZIP 地址，区分 R-18/R-18G。
- 站点 URL 按主机名与路径严格匹配；API 镜像不重写 CDN/OAuth URL；媒体请求不携带 API Key 或 Bearer Token。
- HTTP 模式默认绑定本机，stdio 服务生命周期结束会关闭连接；配置支持与启动目录无关的定位方式。

## 使用与迁移

运行 `uv run media-hunter check` 可检查当前配置。启用动图合成的启动方式为 `uv run --extra animation media-mcp`。原有六个工具名不变，重新启动 MCP 客户端的服务进程后加载新版。

部分失败现在返回 `success: false`，同时保留 `data.files` 或 `data.downloaded`，使用者应同时检查 `errors` 与 `skipped`。`network.retries` 表示包含首次请求的总尝试次数。`timeout` 省略表示不限总时长；若填写须为正数。

下载仍依赖站点本身的可用性和用户凭证权限。E-Hentai 下载图片页实际提供的版本；本次没有新增原始图片配额下载或压缩包购买流程。

源码备份：`backup-before-refactor-20260909-022145/`，包含原代码、测试、文档、依赖文件与示例配置。当前实际配置未被改写。该目录没有 Git 元数据，因此本次未创建提交。
